# 設計の決定記録（ADR）

このフォルダには、Promari SNS Share の設計で下した判断を、1件1ファイルで残します。
形式は Michael Nygard の [Documenting Architecture Decisions](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions)（2011）を土台に、
[MADR](https://adr.github.io/madr/) の「検討した選択肢」「判断の決め手」を足したものです。

## 約束

- 1つのファイルに、1つの重要な判断だけを書く。
- 結論だけでなく、**判断の決め手（目的と制約）・検討した選択肢と捨てた理由・結果（良いことも悪いことも）・見直す条件**を書く。
- 番号は順に振り、使い回さない。
- 判断を覆したときは、古い ADR を消さずに状態を「置き換え済み」にし、新しい ADR へのリンクを書く。
- 当時の記録が無い判断を後から書き起こすときは、そのことと根拠（CHANGELOG・記事など）を明記する。

## ひな形

```markdown
# ADR-NNNN: <判断を短い名詞句で>

- 状態: 提案 / 採用 / 廃止 / 置き換え済み（→ ADR-NNNN）
- 記録日: YYYY-MM-DD

## 背景
いま何に困っていて、どんな力（要求・制約・事情）が働いているか。事実だけを書く。

## 判断の決め手
- 目的:
- 制約:

## 検討した選択肢
1. <案>：利点／欠点（捨てた理由）
2. …

## 決定
「〜にする」と能動の文で書く。

## 結果
良いことも悪いことも、決定のあとに生じる状況をすべて書く。

## 見直す条件
どの前提が変わったら、この判断を見直すか。
```
